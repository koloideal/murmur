# murmur

Личный слой непрерывности между Android-телефоном и Wayland-ноутбуками:
синхронизация уведомлений с двусторонним закрытием, телефон как родной
MPRIS-плеер, общий буфер обмена — со сквозным шифрованием через
zero-knowledge релей на твоём сервере или чистой LAN-семьёй вообще без
сервера.

## Архитектура

```
                    serverful-топология
 phone ──WSS──▶ murmurs (релей) ◀──WSS── murmurd × N ноутбуков
                 │
                 └─ видит: id устройств, размеры фреймов, тайминги
                 └─ не видит: plaintext, семейный ключ, любой контент

                    serverless-топология
 phone ◀──UDP-маяки / прямой TCP──▶ ноутбуки   (ничего не покидает подсеть)
```

Обе топологии несут **один и тот же формат запечатанного конверта**. В
serverful-семье LAN работает быстрым путём: прямая TCP-копия каждого
конверта соревнуется с релейной и обычно выигрывает на порядок по
задержке; проигравшая отбрасывается дедупликацией по sequence number —
избыточные транспорты чисто аддитивны, мёртвый LAN-линк не может съесть
сообщение.

## Модель угроз

Релей считается враждебным.

- **Семейный ключ** `K` (32 байта) генерируется локально первым
  устройством и раздаётся только внутри пейринг-рукопожатия. Релей его
  не видит никогда.
- Payload каждого фрейма — `XChaCha20-Poly1305(K, случайный 192-битный
  nonce)`. До релея доходят шифротекст, id устройства, размер, тайминг.
- **Пейринг** на эфемерном X25519; приглашение верифицируется
  симметричным 6-значным SAS из обоих публичных ключей и транскрипта
  сессии — релей с MITM-подменой ключей даст разные коды на двух экранах.
- **Auth-токены** — 32 байта на устройство; релей хранит только
  `SHA-256(token)`. Отзыв — один бит в реестре, живое соединение убивается
  мгновенно, в протоколе заложен `KeyRotate` для ротации семейного ключа.
- Релей **live-only по дизайну**: ни очередей, ни истории, ни хранимого
  контента. На сервере просто нечего эксфильтровать.

## Корректность в плохих сетях

Интересно в этом проекте не столько «что», сколько «как» — машинерия,
держущая согласованность на флапающем Wi-Fi, перенумерации DHCP,
телефонных хотспотах и роуминге между подсетями:

- **Выбор активного узла без координатора.** Каждый ноутбук вычисляет
  своё presence-состояние (`active`/`idle`/`locked` из `ext-idle-notify-v1`
  + logind `LockedHint`) и рассылает его. Каждый узел вычисляет одну и ту
  же детерминированную функцию от одинаковой карты presence — активен тот,
  кто в `active` со свежайшим ts перехода, ничья разрешается device id.
  Ни протокола выборов, ни координатора, эхо-штормы буфера обмена
  невозможны структурно.
- **Анти-эхо буфера.** Узел хранит хэш последнего отправленного/применённого
  клипа; применение удалённого взводит `expected_hash`, чтобы локальный
  watcher не разослал его обратно. Клипы менеджеров паролей давятся по
  MIME-маркеру `x-kde-passwordManagerHint` до того, как покинут машину.
- **Дедупликация по seq.** Монотонные sequence number на отправителя
  (сеются от wall clock при старте — перезапущенный демон не реплеит) —
  релей, реконнекты и избыточные транспорты могут дублировать, но не
  переупорядочить или воскресить.
- **Самоаутентифицирующееся обнаружение.** LAN-маяки сами являются
  запечатанными конвертами: только член семьи может выдать открывающийся
  фрейм, поэтому рукопожатие не нужно, а чужой бродкастер получает лишь
  отброшенный пакет. Ноутбуки дайлят маяки телефонов и наоборот — максимум
  один линк на пару, без штормов соединений.
- **Супервизия повсюду.** На Android каждый долгоживущий цикл-актор
  (accept, dial, beacon, relay) работает под супервизором с перезапуском;
  ноутбуки редиалят запомненные адреса пиров и госсипят `DialHint` — линки
  восстанавливаются через DHCP-смены. Реконнекты — экспоненциальный backoff
  с jitter; Android дополнительно ретраит мгновенно по коллбэкам
  `ConnectivityManager` о смене сети.

## Интеграция с десктопом — нативная, не эмулированная

Ноутбучная сторона написана на настоящих Wayland/freedesktop-примитивах,
и телефон перестаёт быть особым случаем где-либо в стеке:

- **MPRIS2** (`org.mpris.MediaPlayer2.murmur` через zbus): телефон —
  обычный системный плеер — медиаклавиши, `playerctl`, виджеты
  waybar/swaync работают без изменений. Позиция экстраполируется локально
  между апдейтами с сигналами `Seeked` при коррекции; обложки отдаются
  content-hashed `file://` URL.
- **Буфер обмена** через `ext-data-control-v1` — настоящие события
  selection, не поллинг; `text/plain`, `text/uri-list`, `image/png`.
- **Уведомления** через `org.freedesktop.Notifications`: закрытие маппится
  двусторонне (закрытие где угодно — включая сам телефон — гасит везде,
  с защитой от петель).
- **Островок waybar** (hyprland): статус синка, направление клипборда и
  медиа-виджет с плавающим попапом плеера. Попап позиционируется чтением
  точной геометрии виджета из **AT-SPI-дерева** waybar — без скриншотинга,
  без захардкоженных офсетов. Наведение на название трека переводит
  композитор в клавиатурный сабмап — медиа-хоткеи работают без открытия
  чего-либо.

## `murmurt` — релоцируемая установка одним бинарём

Островок поставляется внутри `murmurt` — самодостаточного Rust-бинаря
(ассеты вкомпилированы: скрипты, OFL-шрифты, конфиг-сниппеты):

```
murmurt install     # пишет скрипты/шрифты/dbus-сервис, маркер-мерджит
                    # waybar jsonc/css + hyprland-конфиги (идемпотентно,
                    # backup-once, не трогает ручные конфиги)
murmurt doctor      # аудит зависимостей с подсказками под дистрибутив
murmurt geometry    # AT-SPI-проба геометрии островка для попапа
murmurt uninstall   # снимает маркер-блоки, удаляет файлы, всё
```

## Устройство репозитория

| Пакет | Стек | Роль |
|---|---|---|
| `server/` | Rust | `murmurs` — тупой аутентифицированный релей. Live-only, ноль хранимого контента. Статический musl-бинарь. |
| `laptop/` | Rust workspace | демон `murmurd` + CLI `murmurctl` + установщик `murmurt`. |
| `mobile/` | Kotlin | Android-агент: notification/media listeners, share и process-text таргеты. |
| `shared/` | Rust | `murmur-proto` — конверт, крипто, типы сообщений, общие для релея и ноутбуков. |

`murmurd` строго фича-на-модуль: фича — это файл с конструктором
`feature()` (фильтр входящих + `run(ctx)`), одна строка в реестре.
Добавление возможности в систему: один новый вариант `Message` в
`murmur-proto`, один файл, одна строка. Админка каждого демона —
newline-JSON по unix-сокету; конфиг-файлы — persistence, а не интерфейс:
демон — единственный писатель.

## 🚀 Быстрый старт

Всё ставится из релизных бинарей — тулчейны не нужны.

**1. Релей** (любой твой Linux-бокс, root):

```console
$ curl -fsSL https://raw.githubusercontent.com/koloideal/murmur/main/install-server.sh | sudo sh
==> bootstrap code: T45K-TP6D      # одноразовый, вооружён пока семья пуста
```

Наверни TLS-прокси (caddy/nginx) на `127.0.0.1:8770` — ноутбуки будут
ходить по `wss://` URL.

**2. Первый ноутбук** (под пользователем, без root):

```console
$ curl -fsSL https://raw.githubusercontent.com/koloideal/murmur/main/install-client.sh | sh
$ murmurd pair --server wss://murmur.example.org --code T45K-TP6D
bootstrap pairing — verification code: 452690       # сверка: murmurs bootstrap-code
$ systemctl --user start murmurd && murmurd doctor
```

Первое устройство, использовавшее bootstrap-код, становится основателем
и минтит семейный ключ локально.

**3. Телефон:** возьми `murmur-android.apk` из
[Releases](https://github.com/koloideal/murmur/releases)
(дружит с Obtainium). На ноутбуке `murmurctl invite`, сканируй QR —
инвайт несёт URL сервера в себе.

**4. Ещё ноутбуки:** `murmurctl invite` на любом члене семьи, затем
`murmurd pair --code …` на новом.

**Serverless?** Пропусти релей совсем — на первом ноутбуке:
`murmurd init --kind serverless --name my-laptop`, затем `murmurctl invite`
и сканируй телефоном. Только LAN, ничего не покидает твою сеть.

Предпочитаешь собирать сам? `cargo build --release` в `server/` или
`laptop/`, `./gradlew assembleDebug` в `mobile/`.

## 📄 Почему не KDE Connect / Apple Continuity / Tailscale

KDE Connect нужна общая LAN. Continuity нужна Apple-техника с обоих
концов. Tailscale нужен их координатор. murmur не нужно ничего из этого —
сервер, который у тебя уже есть и который не может прочитать ни байта из
проходящего через него; а для LAN-семьи — даже его.
